# Validation Plan: openai-model-resolution

**Date**: 2026-09-18

## Happy Path Scenario
Given a `kind = "openai"` route upstream configured with `model_family = "gpt-5"` (no static `model` pin) against an upstream whose `/v1/models` catalog lists `gpt-5.3-codex` (Responses-API-only, needs `max_completion_tokens`), `gpt-5.1-codex-max` (deprecated), and `gpt-5` (chat/completions, `max_tokens`), when a client sends an Anthropic-shaped `tool_use` request through consolette, then consolette resolves candidates newest-first, discovers `gpt-5.3-codex` requires `/v1/responses` and `max_completion_tokens`, sends the real request there, translates the Responses-API response back into an Anthropic-shaped `tool_use` response, caches the winning `(model_id, endpoint, token_param)` tuple keyed by `"gpt-5"`, and every subsequent request for that family skips resolution entirely (cache hit, no `/v1/models` call, no probe).

## Test Stack
- **Unit**: `cargo test`, in-module `#[cfg(test)] mod tests` blocks colocated with the code under test (matches this repo's existing convention — see `src/providers/openai.rs:777` and `src/routing/router.rs`'s `dispatch_should_*`/`from_config_should_*` tests). Pure-function tests (classification, ranking, filtering, probe-body shape) need no async runtime or mock server.
- **Integration**: reuse `src/cost_metrics/test_support.rs::MockServer` (hand-rolled `axum`/`tokio` local server, chosen in that project's plan over adding a `wiremock`/`mockito` dependency — see that file's module doc comment) for all HTTP-mocking needs in Phase 2/3/4 resolution and Responses-API tests. **Gap to close during implementation, not deferred silently**: `MockServer::start` currently hardcodes a single route (`POST /v1/messages/count_tokens`, `src/cost_metrics/test_support.rs:118-120`) — Phase 2/3 tests need `GET /v1/models`, `POST /v1/chat/completions`, and `POST /v1/responses` handlers instead. Extend `MockServer` to accept a route table (or add sibling `start_openai(...)` variant) rather than reinventing a second mock server, per plan.md's explicit rejection of `src/providers/openrouter/models.rs:127-215`'s independent reinvention of the same pattern (Epic 2's "Test infrastructure" note). This extension is infrastructure work implied by Phase 2's Files column but not its own story in plan.md — flagging it here so it isn't missed during Story 2.3.2's first test.
- **E2E / UX**: Rust unit tests exercising the embedded dashboard JS logic (`src/dashboard.rs`'s existing pattern of testing `loadMetrics()`'s ternary logic directly, e.g. `dashboard_js_status_logic_should_check_last_error_kind_before_cooling` at `src/dashboard.rs:699`) for Surface 2; `to_json()` assertions for Surface 3; one manual documentation-review checklist item for Surface 1's "operator reads docs" criterion (no automated tooling reads prose for comprehension). The real-ExampleCorp-Model-Gateway path (Story 6.1.3) is `#[ignore]`d and run manually with VPN/SBN Dev Agent access — not part of the automated suite.
