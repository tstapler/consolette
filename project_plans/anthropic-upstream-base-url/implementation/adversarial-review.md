## Concerns

- [ ] **Phase 1 / Story 1.1.1** — Three acceptance criteria (omitted `base_url` defaults correctly, explicit override honored, typo'd field rejected) but only two tasks (1.1.1a schema change, 1.1.1b `Config::default()` fixture update). No task explicitly budgets time to *write* the tests that prove those three criteria — the plan treats them as automatically satisfied by the schema shape rather than as deliverables. `src/config/schema.rs`'s existing test module already has the pattern to copy (e.g. the Openrouter unknown-field-rejection test around line ~502-510), so this is cheap, but as written it's an unbudgeted, untracked task. Remediation: add an explicit Task 1.1.1c ("add 3 unit tests for base_url default/override/typo-rejection in schema.rs's `#[cfg(test)] mod tests`"), ~5 min.

- [ ] **Phase 2 (compiler-driven fixups) vs Phase 3 / router.rs:89** — Phase 2's Story 2.1.1 lists exactly 3 bare-match-arm sites to fix (`entrypoint/mod.rs:173`, `config/validate.rs:44`, `server_tools/mod.rs:217`) and calls this "compiler-driven call-site fixups." But `routing/router.rs:89`'s `build_providers` match arm — `UpstreamKind::Anthropic => Arc::new(AnthropicProvider::new(...))` (verified at `src/routing/router.rs:88-94`) — is the *same class* of bare-unit-variant match arm and will also fail to compile the instant Phase 1 lands (E0027, pattern doesn't account for the new `base_url` field). The plan defers this specific site to Phase 3 ("Story 3.1.1... wires router.rs's Anthropic arm to destructure `{ base_url }`"), which is fine in effect (the site is covered), but the phase-dependency graph and per-phase framing implies Phase 2 alone restores a compiling build — it does not. If Phase 1+2 are executed/reviewed as an intermediate checkpoint (e.g. by a parallel implementation worker per this repo's SDD workflow), that worker will hit an unaddressed compile error at router.rs:89 that Phase 2's stated scope doesn't warn about. Remediation: either fold router.rs:89 into Phase 2's enumerated sites (with a note that it also needs the `base_url` value threaded, foreshadowing Phase 3), or explicitly state in Phase 2 that the build does not compile until Phase 3 completes.

- [ ] **Missing site: `AnthropicCountTokensEstimator::DEFAULT_BASE_URL` (`src/cost_metrics/estimator.rs:263-286`)** — This type already takes an `Arc<Upstream>` in its constructor (mirroring `AnthropicProvider`) but `AnthropicCountTokensEstimator::new()` unconditionally hardcodes `Self::DEFAULT_BASE_URL = "https://api.anthropic.com"` (line 272) rather than deriving it from `upstream.kind`'s (post-Phase-1) `base_url` field. Story 2.1.2 in the plan touches `estimator.rs:464` but only to fix a *test fixture* Upstream literal to compile — it does not touch `new()`'s hardcoded default. Per `src/cost_metrics/tracker.rs:6-10`'s own comment, this estimator isn't wired into any live code path yet (Epic 2.1/`CostTrackingHook` is still unbuilt), so this isn't reachable today — but it is a real, silent trap for whoever lands Epic 2.1: cost/token estimation would call `api.anthropic.com` even when the configured Anthropic upstream points at a relay, producing wrong auth (the relay's credentials sent to the wrong host, or vice versa) or wrong token counts with no error. Remediation: either (a) fix `new()` now to read `base_url` off `upstream.kind` (few lines, same pattern as `AnthropicProvider::new`), or (b) explicitly document this as an out-of-scope known gap in the plan's Tech Debt Disposition / Unresolved Questions so it isn't silently forgotten when Epic 2.1 ships. As written, the plan doesn't mention this type at all.

- [ ] **Streaming path (`send_streaming_request`) has no dedicated regression test** — Both Phase 4 tests as described (Task 4.1.1b "regression test proving a configured base_url is actually used for outgoing requests," Task 4.1.2a "a non-default base_url leaves a Bedrock-shaped model id unstripped through the full send_request path") name `send_request` / generic "outgoing requests," not `send_streaming_request`. `AnthropicProvider::send_streaming_request` (`src/providers/anthropic.rs:285-364`) independently builds `format!("{}/v1/messages", self.base_url)` and independently calls `Self::normalize_model_name` (line 295) — it is the SSE path real clients (Claude Code) predominantly use. Because both methods read the same `self.base_url` field, a correctness bug in Task 3.1.1a's constructor wiring would likely be caught by the non-streaming test too — but that's an argument from the current implementation's shared-field shape, not a guarantee, and it's cheap insurance against a future divergence (e.g. someone adds a per-transport override later). Remediation: extend the Story 4.1.1 mock-server helper to also exercise `send_streaming_request` (assert the captured request path/body), or explicitly note in the plan why coverage is intentionally left to the shared-field argument.

- [ ] **`normalize_model_name` gating vs. the deliberately-deferred trailing-slash wart** — Story 3.1.2 gates stripping on `base_url != default_anthropic_base_url()`, a raw string comparison. The plan's own Unresolved Questions section defers trailing-slash normalization as "pre-existing wart shared with openai.base_url, not blocking." But that framing undersells a new interaction this feature introduces: for `openai.base_url`, a trailing slash only ever produces a double-slash URL (a request-shape cosmetic issue, arguably tolerated by most servers). For the new Anthropic gate, a config value of `"https://api.anthropic.com/"` (trailing slash, otherwise pointing at the real API) is `!=` the canonical default string, so it silently *disables* Bedrock-model-id normalization against the real Anthropic API — a functional regression (a client sending a Bedrock-shaped model id would get a 4xx from the real API) triggered by a typo that has zero effect on `OpenaiProvider`. This is a materially different failure mode than the "shared identically with openai today" framing suggests. Remediation: either normalize/trim a trailing slash before the equality check (small, contained fix), or explicitly call out in the plan that a trailing-slash default-URL typo has a *functional* consequence for Anthropic (unlike openai) so it doesn't get waved through as pure cosmetic debt.

## Minors

- Requirements.md's "Open questions for planning" (should `base_url` support the same auth-method flexibility already on `Upstream.auth`?) is implicitly answered "no new auth work needed" by the plan's silence — `Upstream.auth` already applies uniformly regardless of `kind`, so there's nothing to add. Worth a one-line explicit note in the plan's Unresolved Questions section confirming this was considered and closed, rather than just not mentioning it, so a future reader doesn't think it was missed.
- Minor duplication of the literal `"https://api.anthropic.com"` across two independent sources of truth after this change: the new `default_anthropic_base_url()` in `schema.rs` and the pre-existing `AnthropicCountTokensEstimator::DEFAULT_BASE_URL` constant in `estimator.rs`. Not a defect (different modules, different eras of code), but if this PR touches `estimator.rs` anyway per Story 2.1.2, it's a low-cost opportunity to point the latter at the former instead of leaving two independently-editable copies of the same magic string.
- `AnthropicProvider::new`'s doc comment update (Task 3.1.1b, ~3 min) has at least two distinct locations to fix, not one: the struct field comment at `src/providers/anthropic.rs:53-56` (explicitly named in requirements.md) AND the module-level doc comment at `src/providers/anthropic.rs:3` ("Forwards requests to `https://api.anthropic.com/v1/messages` unchanged"), which becomes stale too once the base URL is configurable. 3 minutes is plausible but the task description as written only points at one location.
- Verified the plan's "13:1 in-repo precedent" claim for String+default-fn config fields: `src/config/schema.rs` has exactly 13 `fn default_*() -> ...` helpers today, consistent with the cited ratio.
- Verified Phase 5's claim that `references/conf.d/00-providers.toml` currently has exactly 4 `[[upstreams]]` blocks (anthropic, bedrock, openai, gemini) with no active `base_url` line under the anthropic block — accurate.
