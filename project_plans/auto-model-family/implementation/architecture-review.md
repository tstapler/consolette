# Architecture Review: auto-model-family
**Date**: 2026-09-12
**Verdict**: APPROVED — 3/3 prior blockers RESOLVED (re-review 2026-09-12; concerns/nitpicks not re-litigated).
**Constitution**: docs/adr/ADR-000-architecture-constitution.md absent — skipped.

Grounded in: `src/routing/router.rs` (dispatch loop, `effective_candidates`, `record_attempt`), `src/routing/strategy.rs` (ADR-003 purity), `src/routing/health.rs` (index-keyed cooldown), `src/routing/session_overrides.rs` (`metadata.user_id` extraction), `src/metrics/counters.rs` + `src/metrics/mod.rs` + `src/metrics/histogram.rs`, `src/config/schema.rs` / `load.rs` / `validate.rs` / `runtime_overrides.rs`, `src/entrypoint/api.rs` (`post_route`), `src/entrypoint/chat_completions.rs` + `providers/mod.rs:translate_openai_to_anthropic`, `src/providers/openai.rs` (non-2xx → `Validation`), `src/entrypoint/observability.rs` + `src/entrypoint/mod.rs` (`EntrypointState`).

What the plan gets right: A+C over the stats-aware decorator preserves ADR-003 purity (verified: `strategy.rs:1-6` documents the health-blind contract; `router.rs:282-290` does health-filter-then-`select`); no new `RoutingStrategy` impl; parallel per-model map leaves `providers`/`provider_latency` byte-identical; additive-only `/metrics`/`dashboard`/config changes.

## Blockers
- [x] **Story 3.1 / Risk Control — RESOLVED.** The plan specifies alias match on `body["model"]` verbatim in `dispatch` with no role for the route, yet claims rollback via `POST /api/route` hot-swap back to pins. If expansion is unconditional on the alias, a route swap cannot stop family resolution while the client still sends `auto-coding` — rollback would be client-side (opencode provider config), contradicting requirements §Risk Control. — *Remediation:* add an opt-in gate to the route (e.g. `family: Option<String>` on `Route`, additive + `deny_unknown_fields`-safe) and expand only when the active route names the alias; keep unconditional-match only if Risk Control is rewritten to client-side rollback with a test proving route-swap restores pins.
- [x] **Stories 2.1/2.2/3.1 — RESOLVED.** runtime-state ownership unspecified; default reading loses all learning on hot-swap. `MemberStatsMap`, denylist, `ResolutionSnapshot`, `ResolutionCounter`, probe counters are described as living in/near `Router`/`FamilyTable` (`Router::new` gains field, denylist "in FamilyTable"). But `post_route` (`api.rs:121-130`) rebuilds the `Router` via `from_config` while reusing the stable `state.metrics: Arc<MetricsCollector>` — so anything owned by `Router` is wiped on every hot-swap, and stuffing the TTL denylist into config-derived `FamilyTable` conflates immutable config with mutable runtime. Keying by positional upstream index (`DashMap<(usize,String),…>`) additionally goes stale on upstream reorder. — *Remediation:* split immutable `FamilyTable` (config, on `Router`) from `FamilyRuntime` (stats map, denylist, snapshots, counters, probe/hysteresis state) held by `MetricsCollector` (reachable from `dispatch` via `self.metrics`, survives rebuild, mirrors the `session_overrides` carry-across precedent); key by `(upstream_name, model)`, not index.
- [x] **Story 1.2 — RESOLVED.** FreeGuard bypassable via hot-swap (money-safety invariant). FreeGuard is specified "at load," but `post_route` calls `crate::config::validate_references` directly (`api.rs:107`), never `config::load` — a paid member ID can be injected into the free family at runtime past the guard. `validate_references` (`validate.rs:16-40`) only checks name existence and has no paid-member error variant. — *Remediation:* add a `ConfigError` variant (e.g. `PaidMemberInFreeFamily{alias, member}`), invoke FreeGuard inside `post_route` alongside `validate_references`, and add a `post_route`-rejects-paid-in-free test mirroring `post_route_rejects_unknown_upstream`.

## Concerns
- [ ] **Story 3.1/3.3 — strategy × family interaction unspecified.** Ranked-order expansion assumes first-healthy-wins, but `WeightedStrategy::select` (`strategy.rs:46-63`) samples randomly — on a `weighted` route the rank order, hysteresis, and ExplorationProbe are meaningless. — *Remediation:* specify the family route must be `fallback` (validate at load or force `FallbackStrategy` for alias requests) with a test.
- [ ] **Story 3.2 — first-404 behavior unspecified.** OpenRouter non-2xx maps to `ProviderError::Validation` (`openai.rs:249,285`), and dispatch returns immediately on `is_validation` (`router.rs:335-338`) with no failover — so the *first* request hitting a newly-delisted member fails the whole request; the denylist only protects subsequent ones. AC1 covers steady state only. — *Remediation:* either explicitly accept first-failure-then-denylist (test it) or design a scoped intra-family 404-continue (only 404-status, only while family members remain, never touching the shared fast-return otherwise).
- [ ] **Epic 4 / Story 6.1 — session pins dead on the opencode path.** `extract_session_id` reads `body.metadata.user_id` (`session_overrides.rs:32-37`), but `chat_completions.rs:50` dispatches `translate_openai_to_anthropic(&body)`, which rebuilds a fresh body with only model/max_tokens/messages/stream/system/temperature (`providers/mod.rs:252-257`) — `metadata` is dropped, so pins never apply to `/v1/chat/completions`, the named opencode consumer. — *Remediation:* carry `metadata` through the translation or extract the session id pre-translate in `chat_completions.rs`; else scope Epic 4 to `/v1/messages` explicitly.
- [ ] **Stories 2.1/2.2 — ProviderError→stats classification table missing.** "Exclude auth/validation/429 via predicates" names the mechanism (predicates verified at `providers/mod.rs:91-106`) but not the full mapping: `Timeout`/`Upstream{5xx}`→quality window; 429→backpressure (latency sample or nothing?); auth/validation→ignored; `ModelUnsupported`→denylist feed rather than error-rate. `record_attempt` dual-write cannot be tested without per-class write rules. — *Remediation:* specify the table + whether each class writes error-bit, latency sample, both, or neither.
- [ ] **Story 3.1 / glossary — alias/model/upstream all raw `String`; unknown-alias behavior undefined.** `UpstreamRef.model: Option<String>` and `SessionOverride.model: Option<String>` already show the primitive-obsession shape; adding `FamilyMember{upstream, model}` as strings risks alias↔model-namespace confusion in `record_attempt` once it threads the *resolved* ID. An `auto-*` model with no configured family currently leaks verbatim upstream (dispatch overwrites only when `chosen.model` is `Some`, `router.rs:307-314`). — *Remediation:* introduce `FamilyAlias`/`ModelId` newtypes, resolve alias→ranked type once at the dispatch seam, and specify unknown-alias handling (prefer local `Validation` error over leaking garbage to OpenRouter).
- [ ] **Story 5.1/5.2 — family read path incomplete.** The dashboard card links to `GET /api/route`, but `get_route` returns `Route` only — family membership is invisible there; and the `/metrics` `family` section read path depends on the Blocker-2 ownership decision. — *Remediation:* expose families for reads (additive field or `GET /api/families`) or drop the link; read snapshots via `state.metrics` per the Blocker-2 remediation.

## Nitpicks
- Story 1.1 task 4 misdirected: `RuntimeOverrides::apply` only replaces `routes` (`runtime_overrides.rs:70-74`), so families survive hot-swap with zero changes — reduce to a rebuild-path test.
- conf.d `Vec` merge is array-replace (per `runtime_overrides.rs` docs citing ADR-001): document single-fragment convention (`20-family.toml`) in Story 1.1 so split family fragments don't silently wipe each other (same pre-existing footgun as `[[upstreams]]`).
- MemberStats latency should compose `DurationHistogram` (`histogram.rs:13-50`) per member instead of copying its `Mutex<VecDeque>` shape — reuse tested windowing/percentile code.
- Prefer a `with_family_table` builder over changing `Router::new`'s signature — ~10 existing test call sites (`router.rs`, `observability.rs`, `messages.rs`, `chat_completions.rs` tests) churn otherwise.
- Unresolved Questions carry "blocks Epic N" labels but all have workable defaults — relabel decided-with-default and resolve alias naming (the one true input, owner Tyler) before Epic 1.
- Cost attribution uses the pre-dispatch requested model (`chat_completions.rs:43-47`, `messages.rs:37-41`), so family traffic prices the alias (lookup `None` → cost-blind). Pre-existing imprecision shared with route pins, but note it explicitly.
- Denylist TTL value unspecified in Story 3.2 — pick a default (e.g. 1h) so the story is testable.
- Story 3.3 probe target eligibility unspecified — "best non-pick" must exclude denylisted/cooled members; state it.
