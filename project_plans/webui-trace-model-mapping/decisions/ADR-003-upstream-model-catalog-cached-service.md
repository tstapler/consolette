# ADR-003: Upstream model catalog as a cached background service on a new endpoint

**Status**: Accepted (planning, 2026-10-09)

## Context
`GET /api/models` (`src/entrypoint/api.rs:54-87`) reloads config from disk, rebuilds every provider (`build_providers`) and calls `list_models()` serially per request: no cache, no refresh time, no per-upstream timeout, errors inlined as untyped `{error}` strings that are `ProviderError` display text (which can carry upstream bodies, see `src/providers/mod.rs:41,49-50`). The UI never calls it. All five adapters implement `Provider::list_models` (anthropic `:574`, bedrock `:904` via control-plane `ListFoundationModels` returning base model ids, gemini `:497`, openai `:865`, openrouter `:656`).

## Decision
1. New `src/routing/model_catalog.rs`: `ModelCatalog` (state: `RwLock<HashMap<UpstreamName, UpstreamModels>>`, `UpstreamName` from the leaf `src/metrics/ids.rs`). It reuses the live router's already-authenticated providers through a new `Router::providers_named() -> Vec<(UpstreamName, Arc<dyn Provider>)>` accessor (`Router.providers` stays private). Names are stored in a new `Router.provider_names` field set by a `with_provider_names` builder that `from_config` calls (`from_config` currently discards names at `router/mod.rs:557-560`); `RouterDeps` (36 `RouterDeps {` occurrences) and `Router::new` are unchanged, and `providers_named()` returns empty when the names are absent or mismatched in length. Scope is every configured upstream; config warnings (item 5) cover the primary route only. Fan-out uses a `JoinSet` and `tokio::time::timeout` (10 s) per upstream. No new crates.
1a. **Refresh policy (revised): refresh is opt-in or on demand, never an unconditional timer.** Refreshing calls each provider's auth path (exec-based credential helpers via `ExecCredentialCache`, the AWS default chain for Bedrock `ListFoundationModels`, Gemini's undocumented endpoint), which can prompt for SSO, hit rate limits or cost money. `model_catalog.refresh` is `on_demand` (default: `GET /api/model-catalog` is a pure read with no side effects; **the Models view never refreshes on open**: it renders the cached snapshot with its age and an explicit "Refresh now" button (page-level and per upstream), and a never-refreshed upstream shows "Not loaded yet - press Refresh now" rather than a spinner; the optional `POST /api/model-catalog/refresh?ifStale=true` (refreshes only entries `Loading` or older than the staleness threshold, default 30 min, and returns the cached snapshot immediately) stays on the server for interval mode and scripted callers, but the UI does not send it; manual refresh is `POST /api/model-catalog/refresh`, minimum 10 s between manual refreshes. **Accepted risk (decision R1 for Tyler, plan "Risk Control")**: CORS is `Any` on a loopback-only server (`src/entrypoint/mod.rs:260-263`, `:385`), so a web page open in the same browser can send this POST and start credential helpers or paid listing calls; the guards below bound the rate, not the trigger. Optional hardening not applied: reject the POST when an `Origin` header is present and is not the dashboard's own origin (about 0.2 d). Amendment (triad-review UX-7): an automatic POST on page open ran credential helpers and paid calls without a click, contradicting "no hidden refresh"). Guards: one in-flight refresh per upstream, held by an RAII guard that clears on drop so a panicking or aborted refresh task cannot leave it stuck (concurrent triggers coalesce and get the snapshot with `refreshing: true`; `POST /api/model-catalog/refresh?upstream=<name>` refreshes one upstream, 404 for an unknown name, and coalesces onto a running fan-out), the manual throttle applies per upstream from `lastAttemptAt`, and a retry floor of `min_retry_secs` (default 300) measured from `lastAttemptAt` for **all** error kinds on automatic refreshes, so a timeout or 5xx cannot re-fire a fan-out on every request. Because any local process or browser tab that can reach the dashboard port can request a refresh (the server binds `127.0.0.1` only, `src/entrypoint/mod.rs:385`, has no dashboard auth and allows any CORS origin, `:260-263`; and a refresh can run credential flows), the exposure is bounded by single-flight plus the retry floor and stated in the Models view help text, `interval` (`secs`, clamped to >= 300), or `off` (manual only). There is no startup refresh and no hot-swap fan-out by default. An upstream whose last refresh failed with `Auth` is not retried automatically (only the manual button retries). After a route hot-swap in `post_route`, entries for upstreams no longer configured are pruned (`retain` current names) so removed upstreams do not stay as `Stale` forever; the catalog keeps its current name set and entries under one lock and applies a refresh result only for a name still in the set, so a refresh in flight during the swap cannot re-add a pruned upstream; `build_providers` already fetches OpenRouter `/models` per swap (`router/mod.rs:549-556`), so the catalog adds no second fetch there. The mode, defaults and the credential-flow caveat are documented in the config reference and in the Models view help text.
2. Per-upstream state is a sum type: `Loading | Ok | Stale{since} | Error | Unsupported`. A failed refresh never discards the last good list (`Stale` + error kind). `UpstreamModels` carries `models`, `totalCount`, `truncated` (list capped at 1000 ids sent to the UI), `refreshedAt`, `lastAttemptAt`, `refreshing`, `state`, `error: Option<CatalogError{kind, status, message}>`.
3. Errors are classified and sanitized before storage: `kind` in `auth | timeout | rate_limited | upstream | unsupported | other`, `message` is a fixed phrase plus status, never `ProviderError::to_string()`; the full error is logged at `debug` only. A sentinel-secret test asserts the secret never reaches the endpoint or an SSE frame.
4. New endpoints in a new `src/entrypoint/models.rs` (handlers) with only route lines added to `src/entrypoint/mod.rs`: `GET /api/model-catalog`, `POST /api/model-catalog/refresh`. The legacy `GET /api/models` is untouched (compatibility for the Config Editor's free-text -> select comment at `api.rs:45-47`). Additive `DashboardEvent::ModelCatalogChanged` tells the UI to refetch.
5. Config cross-check: the catalog endpoint also returns `configWarnings[]` for models pinned in route config (`RouteUpstreamRef.model`) that the upstream does not list, only when the upstream state is `Ok` or `Stale`. Family-routed upstreams (`model_family`) are not checked (resolved at runtime). Bedrock ids are compared after `BedrockProvider::normalize_model` and the warning text notes that Bedrock lists base ids, not inference-profile ids.
6. Staleness threshold for the UI "stale" label: 30 min in `on_demand` mode, 2 x interval in `interval` mode (product default, adjustable).

## Consequences
- (+) Constant-time UI reads, upstream traffic and credential prompts only when someone clicks Refresh (or opts into interval mode), explicit age/error per upstream (success metric 3), removes per-request provider construction from the new path.
- (-) Two model endpoints coexist until `/api/models` callers migrate (tracked as tech debt).
- (-) Local-backend discovery (`providers/local_discovery.rs`) is a different catalog with its own freshness; v1 does not merge it (backlog).

## Alternatives rejected
- Keep live on-demand and add fields (B3): N upstream calls per page load, one slow upstream blocks the page.
- `moka` TTL cache (B2): TTL expiry loses the stale-plus-error state we need.
- Reusing OpenRouter's `ModelListCache` (B5): coupled to OpenRouter pricing/scoring types; only the pattern is copied.
