# ADR-005: Wire real compression into the request path and measure first byte in the stream tee

**Status**: Accepted as a design (planning, 2026-10-09; default-off decided in triad-review repair iteration 1); **implementation deferred to a follow-up project by Tyler on 2026-10-10** (not part of the webui-trace-model-mapping plan's scope, effort, schedule or success metrics; the decision text below is kept intact for that follow-up). Originally decided by Tyler as scope decision C on 2026-10-09, which superseded the "honest relabel / out of scope" position in the first draft of ADR-002 items 5-6; the 2026-10-10 decision moves the work out of this project but does not reverse the design.

## Context
- The dashboard's token-savings columns (`tokensBefore`, `tokensAfter`, `compressed`) and the compression counters are not fed: `CompressionEngine` (`src/compression/engine.rs:55,109`) is constructed nowhere in the server (grep for `CompressionEngine|compress_request` outside `src/compression/` and `src/bin/` finds nothing), `RequestDetail::from_body` hardcodes `tokens_after: 0, compressed: false` (`src/metrics/mod.rs:99-100`), and `counters/mod.rs:331-337` says the compression atomics are "permanently zero". `session_compaction/*` and `system_prompt/*` are separate features and do not feed per-request savings.
- `firstByteMs` has no source: `record_first_attempt_timing` sets it equal to the headers latency. A stream tee already exists: `CostTrackingStream` (`src/entrypoint/cost_tee.rs:45`) wraps direct streams, the emulated synthesized stream and the chat-completions stream (`chat_completions.rs:73`, before `OpenAiStreamTranslator`).
- `inject_rewind_tool` (`engine.rs:513-526`) unconditionally advertises a `rewind_retrieve` tool; a model calling it returns a `tool_use` the client cannot execute.

## Decision
1. **One ingress compression step**: `apply_compression(&state, &body) -> (Option<Value>, CompressionOutcome)` (`Some(body)` only when compressed; item 2) in `src/entrypoint/compress_step.rs`, called once by `post_v1_messages` (after the response-cache lookup) and `post_v1_chat_completions` (which has no cache lookup; it compresses the translated Anthropic body at the same relative point), before `begin_cost_tracking` / the emulation branch (so the cache key uses the original body and emulated searches compress once, not per loop iteration). `TraceScope::begin` has already run by then, so `begin` records `tokens_before` and `compression_status = off`, and the handler calls `scope.record_compression(CompressionOutcome)` after this step; a cache hit never reaches it and stays `off`. The server-tool emulation decision (`should_emulate`) is evaluated on the original body, so a compression-injected tool cannot change eligibility.
2. **Gated and fail-open, enforceable**: `compression.enabled` (**default `false`, decided**: compression rewrites prompts and advertises tools, so it is opt-in; Tyler may flip the default later with a one-line config change), `compress_floor_bytes` (existing default 1000), `compression.max_body_bytes` (primary, deterministic guard, checked from the already-computed `estimate_tokens` size so it costs no extra serialization), `compression.timeout_ms` (secondary guard) and `compression.max_concurrent`. `CompressionEngine::compress_request` (`engine.rs:109`) is CPU-bound with only in-memory awaits and takes the body by value, so `tokio::time::timeout` alone cannot interrupt it and fail-open needs a clone. Therefore `apply_compression` clones the body once, runs the engine under `tokio::task::spawn_blocking` (driving the async fn with `Handle::block_on`) and awaits the join handle inside `timeout`. A timeout, an engine error, or a `JoinError` (panic) sends the original body, sets `compressionStatus: "failed"` and increments `compression_errors_total`; oversize or no free semaphore permit skips compression (`compressionStatus: "skipped"`, `compression_skipped_total`); `none` means only "engine ran, nothing to save". The caller keeps the original body (`apply_compression(&state, &body) -> (Option<Value>, outcome)`), so the response-cache key and store keep using it. A timed-out blocking task is **abandoned, not cancelled**: it finishes on the blocking pool and its result is dropped (it may leave unused rewind-store entries); the semaphore bounds active plus abandoned tasks because the `OwnedSemaphorePermit` (`try_acquire_owned` before `spawn_blocking`) is moved into the blocking closure and released only when it returns (also on panic), not when the handler's `timeout` fires or the client disconnects. `CompressionEngine` must be `Send + Sync + 'static` (it is built from `usize`, `Arc<RewindStore>` and unit structs, so INFERRED yes); Story 6.1.2 adds a compile-time assertion. The client never sees a compression failure. The clone, both `estimate_tokens` calls and the `spawn_blocking` round-trip are part of the Story 6.1.1 cost baseline.
3. **Rewind tool**: advertise `rewind_retrieve` only if the proxy can serve it; Story 6.1.1 decides between an engine option to skip injection (default if undecided) and proxy-side handling.
4. **Token accuracy**: `tokens_before` and `tokens_after` both use the same `estimate_tokens` (chars/4 of the JSON) on the original and compressed bodies, labelled "est." in the UI; `est_tokens` passed to `dispatch` becomes the post-compression value. `compressionStatus` is `off | none | skipped | failed | compressed`; `tokensAfter` is null for `off`, `skipped` and `failed`. `tokens_before` and the stored original body are post-`clamp_context_budget`.
5. **First byte via the existing tee, with a data-owning slot**: `CostTrackingStream` gets an `Option<FirstByteHook>` through a `with_first_byte_hook` builder (its existing `new` call sites are untouched: 7 in `src`, of which 3 are production sites, plus 1 in `tests/`, VERIFIED by grep at `main` 49ec827). The hook's `Arc<FirstByteSlot>` is created by `scope.first_byte_hook()` when the handler builds the tee (before `finish`, which the tee precedes) and holds the final-attempt send `Instant`, a CAS state (`Pending -> Measured | EndedEmpty | ClientClosed`) and, for `stream: true` only, the final `RequestDetail` snapshot that `finish` fills in later. The tee gets a new `Drop` (none exists today). It fires synchronously (no `await`, no blocking) on the first non-empty `Ok` chunk (`Measured`), on the upstream stream ending or erroring before any byte (`EndedEmpty`), or on tee `Drop` before the upstream terminated (`ClientClosed`, a client abort), always before the tee substitutes `MID_STREAM_ERROR_FRAME`, so the synthesized frame is never a first byte. If it fires with no snapshot yet (tee dropped before `finish`, for example a cancelled handler) nothing is emitted and `first_byte_no_snapshot_total` increments; `finish` then reads an already-resolved state and emits the terminal `firstByteState` directly. When a snapshot exists it takes it, sets `first_byte_ms`/`first_byte_state`/`trace_revision = 1`, replaces the ring-buffer entry if still present and always emits via `RequestTraceData::from_detail` (UI upserts by `requestId`, ignoring a lower `traceRevision`). This also settles the evicted-entry case deterministically and means a streamed row can never stay `pending`. `firstByteMs` shares its origin with `timeToHeadersMs` (send of the final attempt), so it is never smaller than the latency cell. The measured quantity is "first byte of the upstream SSE body" for both ingress formats; the first token follows later (Anthropic `message_start` precedes content) and is backlog. The emulated synthesized stream gets no hook (`n/a (synthesized stream)`).
6. **The tee never alters or delays bytes**: the hook only reads a timestamp; items are returned unchanged and in order; hook failures (poisoned mutex, closed channel) are swallowed. Tests: byte identity over a 1,000-chunk stream with split frames, error/drop behavior asserted at the tee, eviction during a slow stream, and a release-only ratio timing test (<= 1.10).
7. **Display honesty**: a Column Truth Table in `plan.md` defines the displayed value (`n/a (reason)`) for every column in every trace kind (non-stream, stream, cache hit, local, failed, cancelled, compression off); a single UI `naReason` function implements it.

## Consequences
- (+) When implemented: `tokens_before/after/compressed`, the `/metrics` compression counters, `stage=compressed` replay and `firstByteMs` become real, so M1 no longer relies on `n/a` for those two columns.
- (-) Behavior change for users who enable compression (prompts are rewritten); mitigated by the flag, fail-open, and keeping `stage=original` bodies.
- (-) One extra ring-buffer replace and SSE event per streamed request, plus one `RequestDetail` snapshot held until the first byte or stream end.
- (-) Compression adds a body clone and a blocking-pool hop per compressed request (measured in 6.1.1); abandoned timed-out tasks keep running to completion.
- (-) Adds about 9.9 engineer-days (pre-deferral estimate). Tyler deferred this work to a follow-up project on 2026-10-10: `plan.md` "Effort and Appetite" totals Epics 1-5 only (48.4 days against the approved 45) and excludes it. Until it lands, the dashboard shows the defined `n/a (compression off)` / `n/a (not measured)` values and success metric M1 is met through them (requirements M1).
- (+/-) Because the contract fields it fills are shipped early with constant values (Story 1.1.2), the follow-up needs no wire change; it does need to re-baseline its estimates and inherits the a11y carry-over ACs in plan Story 4.1.7.
- (-) The stored compressed prompt (Story 6.1.4) is held in memory only: 100 entries, only when actually compressed, each at most `compression.max_body_bytes` (worst case about 200 MB at the 2 MB default), never in SSE or on disk.

## Alternatives rejected
- Honest relabel only (columns permanently `n/a`): rejected by Tyler.
- New wrapper stream for timing: duplicates the existing tee on three paths.
- Parsing SSE frames for first token in this iteration: more cost and fragility than first byte; backlog.
- Compressing before the cache lookup: changes cache keys and would compress cache-hit requests for nothing.
