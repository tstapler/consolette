# CLAUDE.md

This file guides Claude Code when working in this repository. It was generated by the `code-new-project` skill's library/CLI/MCP-tool path — see that skill's `reference.md` for the rationale, modeled on `tstapler/kibitzer`.

## Stack

- Layout: single-crate
- CLI: `clap` derive subcommands
- MCP: `rmcp` (Rust MCP SDK), served over stdio via the `mcp` subcommand
- Release: `cargo-dist` (`dist-workspace.toml`) triggered by an interactively-pushed version tag (human or Claude Code, using the session's own git credentials — never a CI bot), changelog via `git-cliff` (`cliff.toml`) — see `RELEASE.md`
- CI: GitHub Actions — `.github/workflows/ci.yml` gates PRs (fmt/clippy/test), `.github/workflows/release.yml` (generated by `dist generate`, do not hand-edit) runs on tags
- Pre-commit: Lefthook (`lefthook.yml`) — run `lefthook install` after cloning

## Development Workflow

**Planning and implementing features**: use `/sdd:full` (or the individual phases) for anything non-trivial; `/sdd:quick` for small fixes.

**Cutting a release**: see `RELEASE.md` — Claude Code may push the release tag itself (an interactive, user-credentialed push works fine; only a CI-bot/`GITHUB_TOKEN`-authored push fails to trigger `release.yml`), but only when the user has asked for a release and agreed on the version number, never on Claude Code's own initiative. Do not push a tag from a bot-authored commit (release-please-style), and do not hand-edit `.github/workflows/release.yml` (regenerate via `dist generate` instead).

## Architecture Notes

- Keep transport code (CLI arg parsing, MCP tool handlers) thin; put real logic where it's independently testable.
- `cargo-dist`'s config (`dist-workspace.toml`) and its generated workflow can drift from each other if one is edited without the other — always regenerate via `dist generate` after changing the config.
