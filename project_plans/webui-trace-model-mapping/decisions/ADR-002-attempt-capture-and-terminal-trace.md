# ADR-002: Trace unit, attempt capture via a scope guard, and a single terminal trace

**Status**: Accepted (planning, 2026-10-09); revised twice after architecture and adversarial review

## Context
Verified in `src/routing/router/mod.rs`: `dispatch` (about `:667-795`) loops over candidates; `record_selection` and `update_request_timing` overwrite state in place ("last attempt wins"); `update_request_timing` (`src/metrics/mod.rs:268-305`) is the only `RequestTrace` emitter, is reached only from the `Ok` arm, and hardcodes `status_code: 200` (`:292`). Failures emit nothing. `mutate_request` takes the ring-buffer mutex and scans up to 100 entries per call.

One `Router::dispatch` call is **not** one client request:
- `run_emulation_loop` (`src/entrypoint/messages/mod.rs:374-407`, `src/server_tools/loop.rs:125,165`) calls `dispatch` repeatedly for one client request.
- A response-cache hit (`messages/mod.rs:130-136`) returns before `dispatch`.
- `dispatch_local` (`router/mod.rs:682-684`) returns before `push_request`.
- In axum, a client disconnect drops the handler future, so code after an `.await` in a wrapper never runs; `hold_for_rate_limit_cooldown` can sleep about 45 s (`router/mod.rs:805-808`).

Module layering: `routing` already imports `metrics` (`router/mod.rs:21`); `metrics` imports nothing from `routing`, but already imports `entrypoint::events::RequestTraceData` (`metrics/mod.rs:282`).

## Decision
1. **Trace unit = one client request** (one `request_id`). Emulation-loop iterations, cache hits and local dispatches each produce exactly one trace. `traceKind` is `routed | cache_hit | local`; `iterations` counts dispatch rounds; each `AttemptRecord` carries its `iteration`.
2. **`TraceScope`** (new module `src/metrics/trace.rs`; imports only `metrics` siblings, std and serde: no `routing`, no `providers`. Not a crate-level leaf, because `metrics -> providers`/`entrypoint::events` edges and their cycles already exist; this adds no new edge) is created and **owned by the ingress handler wrapper** as a local variable (or by the `Router::dispatch` compatibility wrapper for existing callers/tests); inner functions only borrow it. It owns the `request_id`, the full `RequestDetail`, the bounded `AttemptLog` (`MAX_ATTEMPTS = 16`) and the requested-model capture. `Router::dispatch_traced(&mut TraceScope, ..)` extracts the loop body; the emulation loop shares that one borrowed scope across its dispatches through a `ScopedDispatch<'s>` struct that implements the existing `Dispatch` trait directly (the closure blanket impl in `src/server_tools/loop.rs:58-62` requires a `'static` future, the trait method itself does not, `:44-56`). The types `AttemptRecord`, `AttemptOutcome`, `RouteReason` (derived by `RouteReason::for_request(&RouteInputs)` over plain values), `RequestOutcome`, `AttemptLog` live in `metrics/trace.rs`; `impl From<&ProviderError> for AttemptOutcome` lives in `providers/mod.rs`; `UpstreamName` lives in `metrics/ids.rs`. Wire conversion (`AttemptTrace`, `RequestTraceData::from_detail`) stays in `entrypoint/events.rs`, which is the **only** place that builds `RequestTraceData`.
3. **Terminal emission survives cancellation, with an explicit finish contract**: `TraceScope::finish(outcome)` writes the ring buffer once and emits once, and is the only normal exit. Each ingress handler is a thin wrapper over an inner function returning `HandlerResult { response, outcome }`, so every return path (400, translation error, emulation failure, `Err(Box<Response>)`) supplies an outcome by type; the wrapper alone calls `finish` then `mark_handler_returned()`, after the inner future and all borrows are gone, and only then does the scope drop (state `Finished`, `Drop` emits nothing). `Drop` of an unfinished scope has two outcomes: handler **not** returned (axum dropped the future) -> `statusCode: 499`, last attempt `cancelled`, `trace_cancelled_total`; handler returned or `thread::panicking()` -> `statusCode: 500`, no `cancelled` attempt, `error!` log, `trace_unfinished_total` (an internal bug marker, never counted as client cancellation). `Drop` is safe because the ring buffer and `event_tx` are `std::sync::Mutex` and `broadcast::send` is synchronous; it must be poison-safe (`unwrap_or_else(PoisonError::into_inner)`) and never panic. There is no `Arc` of the scope (the earlier `Arc<tokio::sync::Mutex<TraceScope>>` design had the loop's `Arc` dropping before the wrapper's `mark_handler_returned`, which would emit a false `unfinished`); the scope cannot be moved into a spawned task because its borrow is not `'static`. An attempt in flight is recorded before the upstream `.await` (a pending attempt in the scope) so that `Drop` can turn it into one `cancelled` attempt; during a hold sleep nothing is in flight and the attempt log is left as is. Tests: drop the dispatch future mid-hold and mid-upstream-await; per-handler pre-dispatch error returns; inner failure after the emulation loop started; mid-stream and poisoned-lock drops; and an axum-level client abort e2e (Task 1.1.3k, week 1-2: this ADR's load-bearing assumption is that axum drops the handler future on disconnect, so it is proven right after the `TraceScope` lands rather than in Epic 5; the cancelled-attempt assertion is added with Task 2.1.2b2).
4. `finish` replaces `update_request_timing` and `set_selected_model*`: build the final `RequestDetail` locally (including `selected_model*` so existing tests keep their meaning once migrated), replace the ring-buffer entry in one lock (a no-op if evicted, counted), then emit `from_detail(&detail)`. No separate "evicted" emit path, and the same rule holds for the stream first-byte re-emit: the hook slot owns a snapshot of the final `RequestDetail` (ADR-005 item 5), so the re-emit also builds from `from_detail(&snapshot)` whether or not the ring-buffer entry still exists.
5. Status code comes from `ProviderError::trace_status() -> u16` (RateLimited and RateLimitedWithRetry 429, Exhausted 503, Timeout 504, Auth 401, Validation(_, s) s, Upstream{status:0} 502, Upstream{status} status, ModelUnsupported 404, ResponseShapeMismatch 502); success is 200; cancelled is 499. It is the canonical upstream-class status, not necessarily the client-visible code (`entrypoint/errors.rs` maps differently per ingress); the drawer says so. For `stream: true`, 200 means status at response headers; a later mid-stream failure is not reflected (backlog).
6. `AttemptOutcome` mapping: `RateLimited` and `RateLimitedWithRetry` -> `RateLimited`; `Timeout`; `Auth`; `Validation` and `ModelUnsupported` -> `Validation`; `ResponseShapeMismatch` -> `ShapeMismatch`; `Upstream`; plus `Shed` and `Cancelled`. Never `ProviderError::to_string()`; no bodies. Each failed attempt also carries a sanitized, closed `AttemptErrorClass` (`auth`, `rate_limited`, `overloaded`, `timeout`, `server_error`, `unreachable`, `client_error`, `bad_response`, `shed`, `cancelled`), mapped exhaustively from `ProviderError` plus status in `providers/mod.rs`, and a short `errorMessage` built only from a fixed per-class phrase and the numeric status (for example `Upstream overloaded (HTTP 529)`), so the drawer can show why an attempt failed without any upstream text reaching the event (a sentinel-secret test pins this). The earlier "no error text at all" rule is superseded for these two allowlisted fields only.
7. Timing honesty: `timeToHeadersMs` = latency to response headers of the final attempt; `totalMs` = wall time of the whole client request; `firstByteMs` is measured by the stream tee (ADR-005) from the same origin as `timeToHeadersMs` (send of the final attempt) and is null where the Column Truth Table in `plan.md` says so. The earlier "honest relabel" of TTFT as always-null is superseded by ADR-005.
8. Counter semantics: `/metrics` `requests_total` counts upstream attempts plus cache hits (existing behavior, `counters/mod.rs:149,165,171`), while traces count client requests; the UI labels the two differently.
9. Cache-hit and local traces are minimal terminal traces (no attempts for cache; one attempt for local). The error rate used by Story 4.1.2 is `statusCode >= 400 && != 499` over routed + local traces, excluding cache hits from the denominator.

## Consequences
- (+) Failures, cancellations, loops, cache hits and local traffic are visible; hot-path locks drop from 3 `mutate_request` per attempt to one replace per request (plus the `begin` push); no `metrics <-> routing` cycle (the earlier plan placed these types in `routing/trace.rs`, which would have created one).
- (-) Every ingress handler gains a scope; a stream that gets a first-byte measurement costs one extra ring-buffer write and SSE event (ADR-005).
- (-) In-flight requests are invisible until they finish (no start event; backlog).

## Alternatives rejected
- Wrapper `dispatch` calling `finish_request` after `.await`: does not run on future cancellation.
- Trace per `dispatch` call: N rows per emulated request, cache hits and local requests invisible, biased error rate.
- `tracing` spans + custom Layer, OpenTelemetry/Langfuse/Helicone, a separate trace store, per-attempt `mutate_request`: see build-vs-buy; unchanged from the first draft.
