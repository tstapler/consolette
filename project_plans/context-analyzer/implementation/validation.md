# Validation Plan: context-analyzer

**Date**: 2026-08-24

## Happy Path Scenario
Given the Baseline (Tyler has no unified view of Claude Code/Codex token spend — only the proxy-only `cost_metrics` dashboard or a disconnected standalone `context-analyzer`), when Tyler runs `consolette serve-cost`, lets the background rescan ingest his `~/.claude/projects/*.jsonl` transcripts into `ContextForensicsStore`, and opens `/dashboard/context` for his most recent session, then the composition panel shows the top token-cost `CompositionCategory` for the pre-selected top-growth turn and the growth chart's 500K threshold toggle visually marks the turn where `cumulative_tokens` crossed it — proving both Success Metrics without leaving consolette or running a second tool. *(Error paths, Codex ingestion, hook capture, and cross-check are variations on/extensions of this core ingest-then-view flow, not equal-priority items — see Phase Dependency Visualization in plan.md, which sequences everything after Phase 1 as additive.)*

## Migration Test

**`migration_should_be_reversible`** (`src/context_forensics/store.rs`, type: Migration)

The plan's own Migration Plan states this store is a **derived, rebuildable cache** — "every table here is a derived cache, fully rebuildable by deleting `context-forensics.sqlite` and letting the next rescan re-ingest every transcript from scratch," with one explicit exception: `hook_events`/`subagents` rows recorded only via live hooks are lost on delete, since they have no transcript-file source to re-derive from. There is no `up.sql`/`down.sql` migration-framework pair to test — schema creation is `CREATE TABLE IF NOT EXISTS`, run unconditionally in `ContextForensicsStore::open()`. The test is designed against that stated model, not a traditional up/down script:

1. **Up**: open `ContextForensicsStore` against a fresh temp path; run `ingest_claude_code_session` against a fixture transcript; assert `sessions`/`turns`/`api_calls` are populated as expected (session count, turn count, token figures).
2. **Simulate a live-hook-only row**: upsert one `HookEventRow` directly (not derivable from any transcript file) to exercise the documented exception.
3. **Down**: delete the sqlite file at that path entirely — the plan's own documented "Rollback procedure."
4. **Re-up**: re-open `ContextForensicsStore::open()` against the same path (recreating the schema from `CREATE TABLE IF NOT EXISTS`) and re-run `ingest_claude_code_session` against the same fixture transcript (simulating the next eager rescan).
5. **Assert reversibility-as-rebuildability**: `sessions`/`turns`/`api_calls` rows match the pre-delete state (same `session_id`, `turn_index`/`cumulative_tokens`, `call_index`/`AnthropicUsage` figures) — proving the transcript-derived tables round-trip correctly through a drop-and-reingest cycle.
6. **Assert the documented exception, not a false "full restore" claim**: the `HookEventRow` from step 2 does **not** reappear after the drop+reingest, because it has no transcript-file source — matching the plan's explicit "those are lost on delete" statement rather than asserting a stronger guarantee the design doesn't provide.

## Test Stack
- **Unit**: Rust built-in `#[test]` + `assert!`/`assert_eq!`, no additional assertion crate — matches the existing convention in `src/claude_code_session/transcript.rs` and `src/claude_code_session/omission_cache.rs`. In-module `#[cfg(test)] mod tests` blocks, consistent with every existing file this plan mirrors.
- **Integration**: Same `#[test]` harness; `tempfile::NamedTempFile`/`TempDir` for real sqlite files and fixture `.jsonl` transcripts (mirroring `transcript.rs:473`'s pattern), `axum::body` request tests against the router (mirroring `cost_metrics/server.rs`'s existing test module) for HTTP routes, and direct `ServerHandler` dispatch calls for MCP tool tests (mirroring `CompactionMcpServer`'s own `#[cfg(test)]` entry point). No separate `tests/` integration-test binary — all colocated with the code under test, matching this codebase's existing pattern.
- **E2E / UX**: Playwright (`ui-playwright` skill as the implementation model) against `dashboard.html` served by a locally-running `consolette serve-cost` test instance seeded via `ContextForensicsStore` fixtures — no SPA framework in this stack, so Playwright drives the rendered HTML/vanilla-JS directly. Accessibility color/contrast and CLI stdout/exit-code criteria (19, 20, 22–24) are manual checklist items — not meaningfully automatable with Playwright's DOM-level assertions or out of Playwright's scope entirely (CLI, no browser).
