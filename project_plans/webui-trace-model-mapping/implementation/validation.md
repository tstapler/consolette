# Validation Plan: webui-trace-model-mapping

**Date**: 2026-10-09

## Happy Path Scenario
Given the dashboard baseline where every Live Request Traces row shows `unknown`/blank cells and a constant 200 (requirements.md "Baseline"), when an operator sends `POST /v1/messages` with `model: "gpt-4o"` through Consolette while the first upstream returns 529 and the second (pinned to `gpt-4o-mini`) streams a reply, then `/dashboard/overview` shows one row with a real request ID, `gpt-4o -> gpt-4o-mini`, a `fallback` chip, `x2 attempts`, real latency-to-headers, a first-byte cell reading `n/a (not measured)` and a tokens-after cell reading `n/a (compression off)` (real first byte and compression are the deferred Epic 6), and status `200 OK (fell back)`, and Inspect shows both attempts with status and latency, the model source and the Why line.

Failure, cache, local, cancelled, compression-off and catalog cases below are variations on this flow. **Must-pass set**: every row outside the section "Deferred follow-up tests (Epic 6)". Rows in that section are kept for the follow-up project and are not run, counted or required in this project.
