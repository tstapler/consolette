## Prior blocker

- **Compression fail-open budget: RESOLVED.** Verified against `src/compression/engine.rs`: `compress_request(&self, mut request: Value)` (`:109`) has no yield point except `rewind_store.insert(..).await` (`:298`), so `timeout` alone could not interrupt it, and the by-value signature does force a clone. The revised design (size cap first, one clone, `spawn_blocking` driving the future with `Handle::block_on`, `timeout` around the `JoinHandle`, `JoinError` panic mapped to fail-open) is sound: a blocking-pool thread is outside the async context so `block_on` does not panic; `RewindStore::insert` (`src/compression/rewind.rs:63`) is an in-memory cache insert that works under `block_on`; the caller keeps the original body so nothing is lost on any failure; the abandoned-not-cancelled behavior is stated honestly. The clone cost is now in the 6.1.1 baseline together with both `estimate_tokens` calls and the `spawn_blocking` round-trip, and the ACs include a panicking engine and a non-yielding slow engine. Two details remain (Concern 3 and Minor 1) but neither blocks.

## Concerns

- [ ] **Scope ownership contradicts itself (Stories 1.1.3 and 2.1.6, ADR-002 item 3).** The wrapper owns the scope, runs `inner(&mut TraceScope, ..)`, then calls `finish` and `mark_handler_returned`. For the emulation path, Story 2.1.6 says the handler owns `Arc<tokio::sync::Mutex<TraceScope>>` and finishes through its own `Arc`. A scope cannot be both borrowed `&mut` from the wrapper and owned inside an `Arc` in the inner function. If the `Arc` lives in the inner function, it drops when the inner returns, before the wrapper's `mark_handler_returned`, and an unfinished scope then emits a false `unfinished`/`cancelled`; the wrapper also cannot reach the scope to mark it. Recommendation: keep the scope owned by the wrapper and let the emulation closure borrow it (the loop closure is not required to be `'static`: `Mutex<&mut TraceScope>` or passing `&mut` through the loop), which removes the `Arc` and the last-`Arc` test entirely. If the `Arc` stays, put `mark_handler_returned` and `finish` in a single method on the outermost owner and say which one it is. Add a test where the inner function returns `Err` after the emulation loop started.
- [ ] **First-byte slot is built too late for the tee that needs it (Story 6.1.5, ADR-005 item 5).** The design creates the `Arc<FirstByteSlot>` "at `finish`" (Files line: "slot construction at `finish`"). But `CostTrackingStream` is constructed inside the inner handler, after dispatch returns and before the wrapper's `finish` (`direct_stream_response`, `messages/mod.rs:228-250`; `chat_completions.rs:73`). The tee therefore needs the hook before `finish` exists. The tee also gets no `Drop` today (none in `cost_tee.rs`), so the `EndedEmpty` path is new, and the case where the slot fires with no snapshot yet (handler future cancelled between tee creation and `finish`, so the scope emits 499 and the tee drops with an empty slot) is unspecified. Recommendation: create the slot from the scope at tee-build time (`scope.first_byte_hook()` returning an `Arc` whose `detail` is a `OnceLock`/`Mutex<Option<_>>` filled by `finish`); define "fires with no snapshot" as no emit plus a counter. Add that case to the 6.1.5/6.1.6 ACs. Also state that the hook fires on the upstream item before the tee substitutes `MID_STREAM_ERROR_FRAME`, so the synthesized error frame is never counted as a first byte.
- [ ] **Semaphore bound on abandoned tasks only holds if the permit moves into the blocking closure (Story 6.1.2, ADR-005 item 2).** The plan says the `Semaphore` "bounds abandoned plus active tasks" but never says who holds the permit. If the handler holds it across `timeout`, it releases at the timeout while the abandoned task still runs, and the "N permits held by abandoned slow tasks -> next request skips" AC can only pass by accident. Recommendation: acquire an `OwnedSemaphorePermit` with `try_acquire_owned` before `spawn_blocking`, move it into the closure, and release it when the closure returns (including by panic, via drop). This also bounds the case where the client disconnects mid-compression and the join handle is dropped. Add that disconnect case to the ACs.
- [ ] **A cancelled trace needs an in-flight attempt record that nothing creates (Stories 1.1.3, 5.1.1).** ACs require "last attempt outcome `cancelled`" on both drop-mid-hold and the abort e2e. `AttemptLog` records an attempt only after an upstream returns (Story 2.1.2 capture in `dispatch_attempts`), so during an await on a hanging upstream the scope holds no attempt to mark. Recommendation: `dispatch_attempts` pushes a pending attempt (upstream, model, `Instant`) before the `.await` and the scope's `Drop` converts it to `Cancelled` with elapsed time; specify this in 2.1.2 and assert it in the 5.1.1 abort scenario (one attempt, `cancelled`, latency > 0).
- [ ] **Single-flight guard has failure modes the ACs do not cover (Story 3.1.3).** (a) A bare `AtomicBool` stays set forever if the spawned `refresh_all` task panics or is aborted at shutdown; the guard must be an RAII type that resets on drop. (b) The AC "10 POSTs within 1 s -> `catalog_refresh_coalesced_total == 9`" only holds if the fake upstream blocks; a fake that returns instantly makes later POSTs see fresh entries and skip (not coalesce), so the count differs. Specify a gated fake. (c) A refresh in flight during a route hot-swap writes results for upstreams the swap has just pruned, re-adding entries; apply results only for names in the current set (`retain` after writing, or check at write time).
- [ ] **UX-05 (refresh one upstream) has no API, and the busy state conflicts with the new design (Story 3.1.3/3.1.4/3.1.5, `design/ux.md`).** `ux.md` requires a one-click refresh of a single upstream and "Refresh all", but `POST /api/model-catalog/refresh` takes no upstream parameter and the single-flight guard is global, so a per-upstream button cannot be implemented as drawn. The Models view AC also keeps the button busy "until the response", yet the POST now returns immediately with `refreshing: true`; busy must end on `ModelCatalogChanged` or `refreshing: false`. `ux.md` still says the stale threshold is 2x the refresh interval (`:176`) and the page is backed by "`GET /api/models`-style" data (`:155`), while ADR-003 sets 30 minutes and a new endpoint. Recommendation: add `?upstream=<name>` (the guard then needs to be per-upstream or the request coalesces onto the running fan-out and says so), define the busy lifecycle, and update `ux.md`.

## Minors

- `plan.md` and ADR-005 cite `rewind_store.insert` at `engine.rs:190,298`; only `:298` is an insert (`:190` is the compress loop). Fix the cite.
- `compressionStatus: "none"` is also used for timeout, panic, oversize and `busy` (ADR-005 item 2), but the glossary defines `none` as "engine ran, nothing changed". The UI will show "no savings" for a skipped or failed run. Add a `skipped`/`failed` value or carry the reason in the drawer, and keep the Column Truth Table honest.
- Story 6.1.2d does not say the handler keeps the original body for the response-cache key and cache store after `body` is replaced by the compressed body; a shadowed `body` would silently change cache keys on writes. Add one AC (cache store uses the original body).
- `EndedEmpty` also covers a client abort before the first byte, so the drawer text "stream ended before first byte" hides whether the upstream or the client ended it. Acceptable for v1; note it in the help text.
- `block_on` under `spawn_blocking` requires the `Compressor` future only to be run, not `Send`, but the trait object must be `Send + Sync + 'static`; confirm in 6.1.2b that `CompressionEngine` (`SmartCrusher`, `TextCompressor`) meets that bound.
