## Test Stack
- **Unit**: Rust's built-in `#[test]` harness with `assert!`/`assert_eq!`/`assert!(matches!(...))`. No new assertion crate needed — this matches the existing convention in `src/learn/transcript.rs` and `src/bin/mcp-proxy/metrics.rs`. `tempfile = "3"` (already a workspace dependency) provides `tempfile::NamedTempFile`/`tempfile::tempdir()` for sqlite-backed and filesystem-backed unit tests. `async-trait = "0.1"` is already a direct dependency, so `Summarizer`'s async trait (Task 3.1.1a) needs no new crate addition.
- **Integration**: Same `#[test]`/`#[tokio::test]` harness, one level up in scope — exercising two or more modules together (e.g. `parse_session_file` → `build_turns`, or the full `compact_session` orchestration) rather than a single function in isolation. Test doubles: `FakeSummarizer` (Task 3.1.1b) stands in for `ClaudeCliSummarizer` in all CI-required integration tests, so no test depends on the `claude` CLI being installed. Fixture JSONL files are constructed inline as `&str` literals or written to `tempfile::NamedTempFile`s within each test (no separate `tests/fixtures/*.jsonl` directory is specified in plan.md; use inline literals unless a test module grows unwieldy, per Task 6.1.1's note about promoting to `tests/compaction_hook.rs`). `rusqlite` (`bundled` feature, already a dependency) backs all `OmissionCache` integration tests against a real (tempfile-path) sqlite file rather than a mock.
- **API/E2E**: The `consolette compact-session` CLI subcommand (`Command::CompactSession`) is exercised indirectly through `claude_code_session::compact_session()` integration tests (REQ-9's third row) rather than by shelling out to the compiled binary — this matches plan.md's Task 5.2.1d, which specifies testing the orchestration function directly, not a `Command::cargo_bin` process-level test. A true process-level E2E test (spawning the compiled `consolette` binary and asserting on stdout's `"Resume with: claude --resume <session_id>"` message) is not specified in plan.md and is not required by this validation plan; note it as an optional follow-up if a reviewer wants binary-level coverage. The `read_omitted_content` MCP tool's E2E path is covered by REQ-8's `mcp_server_should_serve_read_omitted_content_over_stdio_end_to_end` integration test.
