## Concerns

- [ ] **C1. Task 1.1.3d / Story 2.1.1 / Tech Debt row for `metrics/mod.rs`: "leaf module" claim overstated; pre-existing cycles not named.** Task 1.1.3d says `trace.rs` "imports only `crate::metrics` siblings and std/serde", but Story 2.1.1 requires `AttemptOutcome::from(&ProviderError)` there (an import of `crate::providers`) and `RouteReason::for_request` needs session-pin/strategy inputs. `metrics -> providers` already exists (`src/metrics/counters/mod.rs:220`), so this adds no new package edge, but `providers -> metrics` (`src/providers/openai/resolution.rs:50-51`) and `providers -> routing` (`resolution.rs:54`) mean `metrics -> providers -> metrics` and `metrics -> entrypoint -> routing -> metrics` cycles already exist today. The plan is correct that it does not worsen them, but the honest statement is "adds no new edge", not "leaf". Recommendation: (a) reword to "no `routing` import; `providers` and `entrypoint::events` edges already exist"; (b) have `RouteReason::for_request` take plain inputs (bool/`&'static str`/counts), not router types, so the no-`routing` grep stays true; (c) optionally add a Verify-phase backlog item to move `DashboardEvent`/`RequestTraceData` into a leaf `events` module so `metrics -> entrypoint` can be cut later.

- [ ] **C2. Story 6.1.3 vs Story 2.1.6b / ADR-005 item 1: scope is created before compression runs.** Verified handler order in `src/entrypoint/messages/mod.rs:99-134`: `clamp_context_budget` -> `estimate_tokens` -> cache lookup -> `begin_cost_tracking` -> emulation/dispatch. Story 2.1.6b places `TraceScope::begin` before the cache lookup (needed for `cache_hit` traces); ADR-005 places `apply_compression` after the cache lookup. Story 6.1.3's AC says `TraceScope::begin(.., CompressionOutcome)`, which cannot be satisfied: the outcome does not exist yet when `begin` runs. Remediation: `begin` takes only `tokens_before` and `compression_status = Off`; add `TraceScope::record_compression(CompressionOutcome)` called by the handler right after `apply_compression`; amend the 6.1.3 AC and Story 2.1.3b field wiring. Also note `clamp_context_budget(&mut body)` runs before `begin`, so the "original body" pushed to the ring buffer is post-clamp (document or move `begin` above the clamp).

- [ ] **C3. Story 6.1.2 / ADR-005 item 2: the compression "budget" cannot be enforced with `tokio::time::timeout`.** Verified `CompressionEngine::compress_request` is `async` (`src/compression/engine.rs:109`) but is CPU-bound with a single `.await` (the rewind-store insert at `:298`). A timeout only fires at an await point, so a slow `SmartCrusher` pass runs to completion on the Tokio worker thread, and the AC "takes longer than the budget -> original body sent" will not pass as written; it also blocks the async worker for the full pass (the plan's own proposed p99 is 25 ms at 200 KB). Remediation: run the engine via `tokio::task::spawn_blocking` (or a dedicated small pool) with `timeout` around the join handle, treat `JoinError` (panic) as fail-open, and rely on `max_body_bytes` as the real guard; state in the ADR that a timed-out blocking task is abandoned, not cancelled. Add this to Task 6.1.2c and decide in spike 6.1.1 whether sync `spawn_blocking` is needed at all given the measured p99.

- [ ] **C4. Story 3.1.3 / Task 3.1.3b: `Router::providers_named()` is under-scoped (0.3 d, "accessor only").** Verified `Router.providers` is `Vec<Arc<dyn Provider>>` with no names (`src/routing/router/mod.rs:55`); `from_config` discards names (`:557-560`); `RouterDeps.providers` has the same unnamed type (`:418`) and `RouterDeps {` is constructed at 36 sites (grep over `src` and `tests`). An accessor needs a stored name list. Remediation: add `provider_names: Vec<UpstreamName>` to `Router` set by a builder (`with_provider_names`, same carry-across style as `with_capability`, `:506`), populated in `from_config`; `Router::new` callers (tests) default to `[]`, and `providers_named()` zips only when lengths match. Do not change `RouterDeps` (36-site churn in the highest-churn file). Re-size 3.1.3b to ~0.5 d and add the test for the default/mismatch case. Also note `UpstreamRef.name: String` already exists (`src/routing/strategy.rs:19`), so `UpstreamName` conversion at that boundary is the parse-at-boundary point; say so.

- [ ] **C5. Story 6.1.5 / ADR-005 item 5 vs ADR-002 item 4: first-byte re-emit has no data source when the ring-buffer entry is evicted.** Verified the tee fires on `Poll::Ready(Some(Ok(bytes)))` in `CostTrackingStream::poll_next` (`src/entrypoint/cost_tee.rs:~178-188`), and the hook design is `Arc<FirstByteSlot>` with only an `Instant` and an `AtomicBool`. `record_first_byte(request_id, ms)` then does `mutate_request` (a ring-buffer scan); if evicted it has no `RequestDetail` to pass to `from_detail`, so Story 6.1.5's "emits using the scope data only if cheap; otherwise drops and warns" contradicts ADR-002 item 4 ("no separate evicted emit path"). Remediation: since `finish` already holds the final `RequestDetail`, move/clone it (one allocation, once, only for `stream: true`) into the slot as `Arc<Mutex<RequestDetail>>`; the hook sets `first_byte_ms`, replaces in the ring buffer if present, and always emits. This also makes the Story 6.1.5 evicted-request AC deterministic. Document that `totalMs` for a stream means "to headers", not stream end (the scope is finished before the body streams).

- [ ] **C6. Story 2.1.6b: `Arc<tokio::sync::Mutex<TraceScope>>` in the emulation closure.** Design is sound for cancellation (verified `recent_requests` is `std::sync::Mutex` at `src/metrics/mod.rs:185` and `event_tx` is `Mutex<Option<broadcast::Sender>>` at `:199`, so `Drop` can emit synchronously; dropping the handler future drops the closure's `Arc`, so `Drop` runs). Remaining risks to pin in tasks: (1) the tokio mutex guard is held across the whole `dispatch_traced` await (up to the ~45 s hold sleep, `router/mod.rs` hold path), so nothing else may lock the scope while it runs, and the handler must keep its own `Arc` only for `finish`; the last `Arc` to drop is the one that emits `cancelled`, so a clone leaked into a spawned task would delay the cancelled trace; (2) `Drop` must not `unwrap` a poisoned ring-buffer lock (`.lock().unwrap_or_else(PoisonError::into_inner)` or skip) -- the plan's "no unwrap" convention applies but the Drop path has no test for poisoning; (3) add a test that a stream response finished at headers and then dropped mid-body emits no second `cancelled` trace (finish-then-drop is covered, mid-stream drop is covered only for the tee in 6.1.6b). Add these as ACs to 1.1.3 / 2.1.6.

## Lens checks (summary)

- **TraceScope Drop-based emission**: sound (sync std mutex + `broadcast::send`), subject to C6. Compat `dispatch` wrapper keeps the 36 test/call-site signatures; the real production `dispatch` callers are the two ingress handlers plus emulation loop (`src/server_tools/loop.rs:125,165` call a closure, not `Router::dispatch` directly).
- **CostTrackingStream tee extension**: verified the tee wraps all three streaming paths (`messages/mod.rs:~228-250` direct, emulated synthesized, `chat_completions.rs:73` before `OpenAiStreamTranslator`). Passing bytes through unchanged and a set-once hook in the `Some(Ok(bytes))` arm is a minimal, correct extension; the stream already does per-chunk `buf.extend_from_slice` + frame scan, so the "single AtomicBool load" per-chunk claim is true for the added cost only. See C5.
- **Compression wiring call site**: single insertion point after cache lookup and before `begin_cost_tracking` is correct and verified (`messages/mod.rs:116-134`); see C2 and C3.
- **`Router::providers_named`**: does not exist; see C4.
- **Type-driven design**: sum types (`AttemptOutcome`, `RouteReason`, `CatalogState`, `CompressionStatus`, `TraceKind`, `RoutedModelSource`) and `Option<T>` for unknowns are appropriate. `routedModelSource` + `routedModel` could be a single enum `Routed { model, Pinned|Passthrough }` on the Rust side (nitpick N1).
- **Tech debt table**: every hotspot (router, metrics, entrypoint/mod, messages, api, events, observability, cost_tee, providers) has a disposition; "Extend as-is" entries add no new instance of an existing violation except the router `dispatch` split, which is gated by the "net lines <= 0" AC (Story 2.1.2), appropriately sized as tasks 2.1.2d / 1.1.3e. Refactor-first for the trace table is its own story (1.1.4). OK.
- **Build-vs-buy / patterns**: consistent with Phase 2 (no new crates; `JoinSet` is in tokio).

## Nitpicks
- N1. Model `routedModel` + `routedModelSource` as one Rust enum, flatten for the wire in `events.rs`.
- N2. `CostTrackingStream::new` is called in 8 places (grep over `src` and `tests`); add the hook via a `with_first_byte_hook(Option<_>)` builder to avoid touching every test call (ADR-005 says "takes an `Option<FirstByteHook>`" as a constructor parameter).
- N3. Glossary says `RequestTraceData` "may be re-emitted once for a stream"; Column Truth Table says streamed-stream TTFB is `pending` then real. State the UI upsert/ordering rule (a late first-byte re-emit must not overwrite a newer terminal field) in Story 1.1.2d's `pushTrace` upsert.
- N4. Effort table sums (6.5+9.0+7.75+9.5+5.0+7.75 = 45.5) recompute correctly; the cut-order "Remaining" column is arithmetically consistent.
