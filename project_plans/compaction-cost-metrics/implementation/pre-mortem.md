# Pre-mortem: compaction-cost-metrics
**Date**: 2026-08-15

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | Nothing in the codebase — including the new `serve-cost` binary — ever calls `SessionCompactionPipeline::apply()` outside `#[cfg(test)]`; `grep -rn "\.apply(" src` shows every call site is a test. `serve-cost` constructs the pipeline but Epic 2.3 gives it no route/consumer that feeds real request messages into `apply()`. The feature ships fully tested, but in production `serve-cost`'s tracker never accumulates real data — only the synthetic Epic 4.1 test ever exercises it end to end. | Operator runs `consolette serve-cost`, sends real traffic through their normal proxy entry point, then runs `cost-report <key>` and gets `session_not_found` for every real session, forever. | Add an explicit plan.md epic (before Phase 2) that identifies or builds the actual call site that feeds real proxy traffic into `serve-cost`'s pipeline — or, if none exists yet, state in requirements.md/plan.md that this feature is validated only in a synthetic harness and file the "wire real traffic into a live pipeline" work as a tracked follow-up, not an implicit assumption. | P1 |
| 2 | `PricingTable::price_for(model)` is a bare string match against LiteLLM's snapshot keys, which are typically dated/versioned model identifiers (e.g. `claude-3-5-sonnet-20241022`), while real request payloads may carry aliases (`claude-sonnet-5`, `claude-sonnet-latest`) or a different casing/vendor prefix. Every test in the plan uses hand-picked matching strings, so the mismatch is invisible until real traffic hits it. | Every `CostReport` for real sessions shows `cost_actual: None`/`"pricing_unavailable"` even though tokens are being tracked correctly — the dollar half of "actual-vs-counterfactual cost" silently never populates. | Add an acceptance criterion/test that resolves pricing using the exact model-name strings consolette's own routing table (`src/providers/`) actually produces for live requests, not hand-authored fixture strings — and add a normalization/alias layer in `pricing.rs` if a mismatch is found. | P1 |
| 3 | `SessionCostState.totals_by_tier` is a fixed `[TierTotals; 4]` indexed by a hand-written `tier_index(tier)` that lives in `cost_metrics`, coupled to `CompactionTier`'s 4 variants defined in `src/session_compaction/tiered.rs` — a module this feature doesn't own. Nothing forces `tier_index`/the array size to be updated if a 5th tier is added later (no exhaustive match, no shared constant). | A future PR adds a new `CompactionTier` variant for an unrelated reason; `cost_metrics` either panics (out-of-bounds index) or silently drops that tier's records into the wrong bucket — caught only if someone happens to notice, likely weeks later. | Replace the hand-computed index with an exhaustive `match tier { Off => 0, Micro => 1, Auto => 2, Full => 3 }` (compile error, not silent drift, if a variant is added) instead of a bare cast/formula, and add a `static_assertions`-style or test-time exhaustiveness check tying array length to variant count. | P2 |
| 4 | `AnthropicCountTokensEstimator` calls the real Anthropic API with the *same* API key/account as the operator's live production traffic, once per compaction event, uncached and unrelated to the (separately cached) pricing lookup. Under real load this competes for the same per-key rate-limit budget as actual user requests, and the bounded `Semaphore(4)` only caps `cost_metrics`'s own concurrency — it does nothing to prevent this traffic from tripping Anthropic-side account-level rate limits shared with production calls. | Real user-facing requests start getting 429s from Anthropic during bursts of compaction activity, with no visible link back to the new cost-metrics feature (it looks like a provider outage). | State this shared-rate-limit-budget risk explicitly in requirements.md's Feasibility Risks / Observability Requirements, and make the Anthropic estimator's concurrency cap and/or on/off switch configurable independently of production traffic, with a metric distinguishing count_tokens-call 429s from real-request 429s. | P2 |
| 5 | `CostTrackingHook::post_compact` spawns one `tokio::task` per `apply()` call, each holding a cloned `Value` of pre- and post-compaction messages until it acquires one of only 4 semaphore permits for the Anthropic estimator. Nothing caps the number of spawned-but-waiting tasks; under sustained/bursty compaction volume (many sessions compacting concurrently), queued tasks and their cloned message payloads accumulate in memory ahead of the semaphore, with no shedding or backpressure signal. | Memory usage climbs proportionally to compaction throughput rather than session count during a traffic burst; `serve-cost` becomes memory-pressured or OOMs under load that the existing (untracked) compaction path handled fine. | Add a bounded queue/task cap (not just a bounded *concurrency* cap) in front of the estimator — e.g. a bounded `mpsc` channel that drops/marks-`Abandoned` new estimation requests once a queue-depth limit is hit, with a metric for shed requests, plus a load test in Epic 4.2 that drives compaction volume well above the semaphore's throughput. | P3 |

## P1 Items (address before implementation)
- [x] Failure #1 — Add a plan.md epic (before Phase 2's integration work) that identifies the real call site feeding production traffic into `serve-cost`'s `SessionCompactionPipeline`, or explicitly scope this release as "synthetic-harness-validated only" and track live-traffic wiring as a separate follow-up in Unresolved Questions, so the success metric isn't silently unverifiable in production.
  - Addressed: plan.md's new "Known Limitation: no live traffic feeds the pipeline" section (right after the ADRs line, before "Rework Notes"); mirrored as a new bullet under requirements.md's `## Open Questions`.
- [x] Failure #2 — Add a pricing-lookup acceptance criterion in Epic 1.4 that tests `price_for()` against the actual model-name strings `src/providers/` produces on live requests (not hand-picked fixture strings), and add alias/normalization handling in `pricing.rs` if any mismatch is found.
  - Addressed: plan.md Epic 1.4, new Task 1.4.1e ("Test `price_for` against the real model-name strings `src/providers/` emits on live requests"), plus a note added to the `PricingTable` row of the Domain Glossary.
