# Validation Plan: anthropic-upstream-base-url

**Date**: 2026-09-25

## Happy Path Scenario

Given an operator's `kind = "anthropic"` upstream configured with `base_url = "https://gateway.internal.example/anthropic"`, when `AnthropicProvider::send_request` (or `send_streaming_request`) fires a request, then the outgoing HTTP call hits `https://gateway.internal.example/anthropic/v1/messages` instead of the hardcoded `https://api.anthropic.com/v1/messages`.

## UX Acceptance Tests
N/A — pure infrastructure/config change, no user-facing surface (no `design/ux.md` exists for this project).

## Test Stack
- **Unit**: Rust `#[test]` / `#[tokio::test]`, `assert_eq!`
- **Integration**: local `axum`/`tokio::net::TcpListener` mock server (see plan.md Story 4.1.1's Task 4.1.1a helper, `start_capturing_messages_server`, added directly to `src/providers/anthropic.rs`'s `mod tests` — not shared with the `openai` module's equivalent helper, per plan.md's build-vs-buy Pattern Decision)
- **E2E / UX**: N/A

## Migration / Reversibility
N/A — no schema/DB migration, config-shape change only, caught entirely by `cargo build` (plan.md Migration Plan: the only breakage is at the Rust API level — constructor signatures and ~9-10 match/construction call sites — entirely internal to this crate and entirely caught by the compiler, not a runtime or user-facing migration concern).
